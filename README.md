# 飞猪 AI 旅行规划助手

当前版本：V0.3.1（独立行程地图与真实 POI 自动解析）

## V0.3.1 已实现

- 行程卡“查看路线”进入独立 `/trip-route` 页面，返回后保留原聊天记录、行程和页面状态。
- 新增 Mobile First 的行程路线页：Day 横向选择器、真实地图区域、路线摘要、交通段与纵向 Timeline。
- 接入高德地图 JavaScript API 2.0；地图 SDK、POI 解析与业务 UI 分层，页面组件不直接操作 `window.AMap`。
- 按“城市 + 景点名”调用 PlaceSearch 自动解析真实 POI，并按名称、城市和类型匹配最合适结果。
- 地图内部统一使用 GCJ-02 经纬度；Marker、景点缩略图和 Polyline 共享 `RouteStop.location`，不使用页面百分比坐标。
- Day 切换同步更新地图、路线、摘要、Timeline 和当前景点；地图 Marker 与 Timeline 共用 `selectedStopId`。
- 地图支持自动 fitView、重新定位、原生缩放、缩略图随 Zoom 分级显示和基础碰撞 Offset。
- 单个 POI、图片或地图 SDK 加载失败时局部降级，路线摘要与 Timeline 仍可继续查看。
- 已验证 375×812、390×844、430×932 三种移动端尺寸无横向溢出。

## 高德地图配置

复制 `.env.example` 为 `.env.local`，填入高德 Web 端 JavaScript API 2.0 配置：

```bash
VITE_AMAP_KEY=你的Web端Key
VITE_AMAP_SECURITY_CODE=你的安全密钥
```

未配置 Key 时，路线页会显示地图服务提示，但 Day、摘要和 Timeline 仍可正常使用。

## V0.2.5 已实现

- 根据 `TripRequirement` 动态生成结构化 `TripPlan`，不再按照固定 Day 模板输出长沙行程。
- 38 个长沙 Mock 景点均配置空间片区、适合时段、步行强度、爬山属性及亲子/老人适配信息。
- 同一天优先选择同一空间片区的景点，并按照上午、午餐与休息、下午、晚上的顺序安排。
- `relaxed`、`normal`、`intensive` 分别以每日 3、4、5 个主要活动为基础生成行程。
- 美食、历史文化、自然风景、购物、摄影、亲子和夜生活偏好会改变候选景点权重。
- 老人同行时自动排除爬山项目、降低每日活动数量和强度并增加午间休息；儿童同行时提高亲子、公园与轻松活动权重。
- “不安排爬山”“减少步行”等约束优先于普通偏好，并参与全局重新规划。
- 支持中文序数和 `Day N` 局部修改；只更新目标日期，其他日期保持原样。
- 局部日期约束会保存在对应 `TripDay`，后续预算或全局需求变化重新规划时继续生效。
- 预算、人数、年龄结构、偏好、节奏、酒店或约束变化后重新生成整体行程，并重新运行完整预算计算器。
- 修改结果通过更新提示卡展示，随后重新输出唯一一张最新“行程＋预算”卡。

## V0.2.4 已实现

- 建立与 UI 分离的固定旅行数据层：38 个长沙景点，以及酒店、餐饮、市内交通和上海—长沙城际交通数据。
- 所有价格使用统一 `PriceInfo`，区分 `mock`、`estimated` 和未来可接入的 `realtime` 类型。
- 独立实现门票、酒店房间与晚数、餐饮、市内交通、城际交通和总预算计算服务。
- 门票按实际游客年龄结构计算，并支持多个景点汇总；免费景点所有游客均为 0 元。
- 酒店定价引擎使用 V0.2.3 的档位、房间数和住宿晚数规则。
- 长沙 Demo 会读取生成行程中的实际景点计算门票预算。
- 预算总览显示分类费用、总费用、人均费用、用户预算、剩余或超支金额以及超预算优化建议。
- 行程与预算集中展示在同一张可展开卡片中，不再在行程生成前单独展示预算。
- 用户替换、删除或精简景点后，行程卡与预算同步更新。
- 所有费用界面均明确标记为 Mock 或预计参考价格，并展示非实时价格免责声明。

## V0.2.3 已实现

- 默认每间房最多入住 2 人，房间数统一使用 `Math.ceil(totalTravelers / 2)` 计算。
- 酒店档位为经济型 ¥250、舒适型 ¥400、高档型 ¥650，每间每晚均为 Demo Mock 价格。
- 默认使用舒适型酒店，并支持从自然语言中切换酒店档位。
- 住宿费用按照“房间单价 × 房间数量 × 住宿晚数”计算，住宿晚数默认为旅行天数减一。
- 人数、旅行天数或酒店档位变化后，预算总览中的房间数、晚数和住宿费用自动重新计算。
- 暂不处理儿童不占床、加床、家庭房、三人间、套房及其他真实房型规则。

## V0.2.2 已实现

- 每位已识别游客使用 `Traveler` 保存年龄和儿童、成人或老人类别。
- 只知道总人数时主动询问是否有 12 岁及以下儿童或 65 岁及以上老人，不默认所有游客都是成人。
- Demo 默认年龄规则：儿童 ≤12 岁、成人 13～64 岁、老人 ≥65 岁。
- Demo 默认票价规则：儿童按成人票 50%、成人按 100%、老人免费；免费景点所有游客均为 0 元。
- 游客人数或年龄改变后自动重新识别类别并计算门票，现有行程卡人数同步更新。
- 对话内使用成人票 ¥40 展示可核验的门票试算，并明确提示真实优惠政策以景区票务信息为准。

## V0.2.1 已实现

- 使用 `TripRequirement` 持续保存目的地、出发城市、日期、天数、游客、预算、偏好、节奏、同行关系和特殊要求。
- 从中文自然语言中抽取旅行需求，并将后续回答合并到同一份需求中。
- 根据必填信息的实际完整性驱动对话状态，不再依赖固定的第几轮对话。

- 当前动态行程与价格数据覆盖长沙；其他目的地会完成需求收集，等待后续接入对应城市数据。
